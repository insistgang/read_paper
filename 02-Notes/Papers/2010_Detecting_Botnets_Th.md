## 研究背景与动机

- **为什么要做**：僵尸网络对系统构成严重威胁（如DDoS攻击、信息窃取），需要新的有效检测技术。
- **之前方法的问题**：
    1. 使用**蜜罐**无法主动检测未经其自身的可疑流量。
    2. 监控**标准IRC端口**的流量模式会产生误报，因为僵尸可能运行在非标准端口。
    3. 通信通道没有**简单的特征**可用于检测（如连接长度、字节数不固定）。
    4. 直接分析流量内容或加密流量存在困难。
- **核心矛盾**：需要一种不依赖于分析具体流量内容或端口，而是能够有效识别僵尸网络协同行为的检测方法。
## 关键贡献

1.  提出一种**基于API函数调用拦截**的数据收集机制，监控通信应用程序（如mIRC）的Windows API socket函数调用（如`send()`, `recv()`）并记录到日志文件。
2.  设计并实现一个**日志文件大小变化监控程序**，以固定间隔（每秒）记录各主机日志文件的大小。
3.  提出并实现一个**关联算法**，通过检测不同主机日志文件大小是否**同步变化**（全变或全不变）来区分正常与异常行为。
4.  在**虚拟IRC网络环境**中设计了对比实验，验证了该方法能有效区分正常用户行为与僵尸（sdbot）的攻击行为。
5.  利用**ROC分析**评估了算法性能，确定了检测阈值（约70%）可以在达到100%检测率的同时实现零误报。
## 方法

- **整体框架**：系统分为三个主要部分：数据收集（DLL注入与API钩子）、数据记录（文件大小记录器）、数据分析（关联分析器）。
- **输入输出**：
    - **输入**：运行在目标主机上的通信应用程序（如mIRC）。
    - **输出**：关联分析结果，判断是否存在疑似僵尸网络活动。
- **关键模块**：
    1.  **DLL注入与API钩子模块**：创建一个动态链接库（DLL），将其注入目标进程（如mIRC客户端）。该DLL用自定义函数（如`myrecv()`）替换原生的API函数（如`recv()`），从而拦截所有socket通信调用，并将调用及其参数写入日志文件。
    2.  **文件大小记录器**：一个独立程序，以固定时间间隔（如每秒）扫描并记录所有相关主机上的日志文件大小，形成时序数据。
    3.  **关联分析器**：算法核心（伪代码见Algorithm 1）。它比较时间窗口内各主机日志文件大小的变化状态（有变化记为1，无变化记为0）。如果**所有主机**在某个时间点状态一致（全0或全1），则记为一次**相关事件**；否则记为**不相关事件**。在分析周期内，统计相关事件（CV）和不相关事件（UCV）的数量，并与阈值比较以做出判断。
- **机制直观解释**：僵尸网络中的主机通常会**同时**响应来自僵尸主控者的相同命令（如发起洪水攻击），导致它们的日志文件大小在几乎相同的时间点发生相似幅度的变化。这种**跨主机的同步性**是正常用户行为中很少见的，因此可以作为检测信号。
- **训练方式**：文中未提及传统意义上的模型训练。算法参数（如阈值）通过实验确定。
- **推理流程**：部署DLL和记录器 -> 收集一段时间的日志大小数据 -> 关联分析器计算相关事件比例 -> 与阈值比较 -> 输出警报。
- **与已有方法的差异**：与分析流量内容、端口或模式的传统方法不同，该方法**不关心具体通信内容**，而是关注**由底层系统行为（API调用）反映出来的主机活动同步性**，因此对加密流量和端口变化具有鲁棒性。
