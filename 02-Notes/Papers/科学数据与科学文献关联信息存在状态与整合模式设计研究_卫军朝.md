## 研究背景与动机

- **研究动机**：数据密集型科研范式（Jim Gray 第四范式）下，将科学数据与科学文献关联，使二者有机构成全部科学研究的内容整体，已成为共识。越来越多期刊出版商（Science、Nature、BioMed）、科学数据仓储、知识库平台已开展关联服务：Elsevier 与 PANGAEA、PDB、GenBank 等 40 多个数据仓储合作；Dryad 与众多期刊合作实现数据集到论文的反向查看；国内中科院 ScienceDB 已与 Springer Nature、Cell Press、Elsevier 及《中国科学数据》《科学通报》等 50 余种期刊关联；谷歌学术、OpenAIRE、RD-Switchboard 通过语义实体方式构建数据生态。
- **关联类型归纳（引言）**：当前科学数据与科学文献关联类型可归为四种——① 基于唯一标识符（数据 DOI，最简单）；② 基于元数据（分析内外部特征相似性）；③ 基于语义实体（识别概念/术语，计算语义相似性，可发现 DOI 识别不到的关联）；④ 基于开放框架（统一标准/规范，实现整合与集成、标准化）。
- **核心问题（焦点后移）**：以往研究多关注"如何实现关联"，本文转而研究关联操作沉淀下来的"**关联信息**"本身。论文将关联信息界定为：知识库平台完成数据与文献关联后，对该关联状态进行描述而得到的信息，一般包含科学数据方信息、科学文献方信息、关联状态信息三部分。当前这类信息存在两大问题：
    1.  **描述异构性**：不同平台基于自身元数据方案（DC、DDI、RIF-CS 等）描述关联信息，即使同基于 DC 也各自个性化定制，方式不统一。
    2.  **保存分布性**：关联信息多依附于各机构知识库/数据平台分散保存，难以集中检索利用。
- **研究空白**：国内对关联信息的存在形式、发展现状及如何整合等方面的调查与研究还鲜有涉及，本文意在填补这一空白并为我国统一管理与集成提供参考。

## 关键贡献

- **现状系统调研**：选取 10 个国内外代表性平台（期刊论文库 Elsevier、Europe PMC；科学数据库 Dryad、ANDS；综合性知识库平台 OpenAIRE、RD-Switchboard；国内平台中科院 ScienceDB、全球变化科学研究数据出版系统；以及专门框架/平台 Scholix、Scholexplorer），从关联对象、组织方式、元数据描述、保存方式、发布方式等维度调查关联信息存在状态（表 1）。
- **存在特点提炼**：明确总结出关联信息的两大根本特点——"描述异构性"与"保存分布性"，并指出 Scholix 框架是应对二者、实现互操作的国际主流方案。
- **四层整合模式设计**：构建集中式关联信息整合模式，含"基础数据库层、关联信息转换层、互操作层、中心层"四层（图 3），通过转换层将异构关联信息映射为同质，再经互操作层（OAI-PMH/SRW/SRU/SFX/OpenURL）收割至中心集成库。
- **统一元数据方案设计**：设计三部分元数据（图 4）——科学文献元数据（基于 DC，2 个必备 + 10 余个扩展字段）、科学数据元数据（基于 DDI，2 个必备 + 10 余个扩展字段）、关联关系元数据（8 个必备 + 4 个扩展字段）。
- **中心集成功能设计**：明确中心集成库四大功能（图 5）——采集、解析与去重、组织与存储、互操作与检索，并给出关联信息整合的一般流程（抽取→通用元数据描述→OAI-PMH/API 发布→中心库收割→解析去重重构→检索服务）。

## 方法

本文属调查与模式设计研究，核心方法是文献调研 + 网络调研 + 理论框架构建，无算法/实验模型。

- **整体框架**：两大模块。第一部分调研并分析关联信息"存在状态"；第二部分基于分析结论设计"整合模式"。
- **输入与输出**：
    - **输入**：10 个平台关联信息实践的网络/文献调研数据。
    - **输出**：现状系统分析结论（表 1）+ 四层整合模式（图 3）+ 元数据描述方案（图 4）+ 中心集成功能（图 5）+ 整合一般流程（3.5 节）。
- **存在状态分析（第 1 章，四个维度）**：
    1.  **存在方式**（1.1）：① 依附于各类知识库对自身论文/数据的信息描述中（如 Dryad 的 Related Works 元素、ANDS 基于 RIF-CS 的 relatedInfo 元素、Plos One 的"数据可用性声明"）；② 存在于专门集成平台（Scholexplorer、ScienceDB、全球变化科学研究数据出版系统）。
    2.  **组织方式**（1.2）：① 基于元数据（在原元数据描述上增字段，如 Elsevier 的 Supplemental information / Data availability statement、Europe PMC 的 Associated Data、Dryad 的 Related Works）；② 基于语义实体（OpenAIRE 设计数据源/出版物/数据集/作者/机构/项目/资助等基础实体及关联实体；RD-Switchboard 以数据为中心构建实体关系图，图 1；Scholexplorer 数据模型含 3 个数据实体——源对象/目标对象、关联关系、数据来源）；③ Scholix 框架（规定 6 个核心元数据及子元素、属性、允许值、是否必须，图 2）。
    3.  **发布方式**（1.3）：① 附属发布（关联信息随知识库整体元数据经 OAI-PMH 发布，缺点是无法单独开发利用，需用户从元数据中抽取）；② 转换为 Scholix 标准后发布（ANDS 构建 RIF-CS→Scholix 映射表（表 2）并开发 OAI-PMH Endpoint；Europe PMC 经转换按资源类型封装后通过 API 返回 XML/JSON）。
    4.  **集成方式**（1.4）：以 Scholexplorer 为例——从外部数据源经 API/OAI-PMH 采集 Scholix 元数据包，解析去重后在本地构建关联信息库，提供四类服务：门户网站检索、面向第三方的 Scholix Swagger API、批量数据访问、关联信息下载（自 2018 年起每六个月在 Zenodo 发布完整 JSON 版本）。
- **整合模式设计（第 3 章）**：
    - 信息资源整合模式分集中式、分布式、集中与分布相结合三种；考虑我国机构知识库/期刊库/数据平台建设现状，本文选**集中式**四层模式。
    - 四层：① 基础数据库层（数据中心/期刊出版商/机构知识库/仓储平台等数据源）→ ② 关联信息转换层（设计简洁通用的关联信息元数据标准，映射转换异构信息为同质）→ ③ 互操作层（OAI-PMH/SRW/SRU/SFX/OpenURL 收割）→ ④ 中心集成层（中心集成库完成采集、组织、解析、去重、管理、发布及门户检索）。
    - 元数据方案三部分（文献/数据/关联关系），文献与数据各 2 个必备字段满足关联信息最小化表示。
    - 中心集成功能四项：采集（OAI-PMH 收割 + API 批采 + 数据源自动提交，全量与增量结合）、解析与去重（解析对象唯一标识确定关联双方，去重两类重复——不同数据源相同关联、不同唯一标识但属性相同）、组织与存储（元数据组织 + 语义实体组织相结合）、互操作与检索（API/OAI-PMH 发布 + 网站检索下载 + 统计分析/知识服务）。
- **与已有方法的差异**：相较邱春艳、黄筱瑾、卫军朝（2017）、黄永文等侧重"如何实现关联"的研究，本文将焦点后移至"关联信息"本身，并首次系统调查其存在状态。

## 3. 背景与问题
- **范式驱动**：数据密集型科研（第四范式）下，数据与文献关联构成完整科研素材已成共识，Science/Nature/BioMed、Elsevier/Dryad/ScienceDB、谷歌学术/OpenAIRE/RD-Switchboard 等已广泛开展关联服务。

- **关联信息界定**：平台完成关联后对关联状态的描述信息，含科学数据方、科学文献方、关联状态三部分。
- **两大核心问题**：① 描述异构性——各平台基于自身方案（DC/DDI/RIF-CS）描述，即便同基于 DC 也各自定制；② 保存分布性——多依附各机构知识库分散保存。
- **研究空白**：国内对关联信息存在形式、现状、整合的调查研究鲜见，本文焦点从"如何关联"后移到"关联信息本身"。

## 4. 核心贡献
- 国内较早系统调查 10 个平台的关联信息存在状态（表 1），覆盖期刊库、数据库、综合平台、专门框架/平台。
- 提炼"描述异构性""保存分布性"两大存在特点。

## 5. 方法详解
研究方法为文献调研 + 网络调研 + 理论框架构建，分"存在状态分析"与"整合模式设计"两大模块。

- **存在状态分析（四维度）**：
    - 存在方式：依附知识库元数据 vs. 专门集成平台（Scholexplorer/ScienceDB/全球变化系统）。
    - 组织方式：基于元数据（Elsevier/Europe PMC/Dryad 增字段）、基于语义实体（OpenAIRE/RD-Switchboard 实体关系图；Scholexplorer 数据模型含 3 实体：源/目标对象、关联关系、数据来源）、Scholix 框架（6 核心元数据）。
    - 发布方式：附属发布（随整体元数据经 OAI-PMH 发布）vs. 转换为 Scholix 后发布（ANDS 用 RIF-CS→Scholix 映射表 + OAI-PMH Endpoint；Europe PMC 按资源类型封装经 API 返回 XML/JSON）。
    - 集成方式：Scholexplorer 全流程（采集/收割→解析去重→本地构库→门户/Swagger API/批量访问/下载，2018 起每半年 Zenodo 发布 JSON）。
- **整合模式设计**：
    - 选型：信息资源整合分集中式/分布式/混合三种，本文据我国建设现状选集中式四层。
    - 四层：基础数据库层（数据源）→ 关联信息转换层（设计通用元数据标准，映射异构为同质）→ 互操作层（OAI-PMH/SRW/SRU/SFX/OpenURL 收割）→ 中心集成层（中心库采集/组织/解析/去重/管理/发布 + 门户检索）。
    - 元数据：文献（DC）+ 数据（DDI）各 2 必备 + 10 余扩展；关联关系 8 必备 + 4 扩展。
    - 中心功能：采集（OAI-PMH/API/自动提交，全量+增量）、解析去重（解析唯一标识定双方，去两类重复）、组织存储（元数据 + 语义实体相结合）、互操作检索（API/OAI-PMH 发布 + 网站检索下载 + 统计分析）。
- **整合一般流程（3.5）**：基础库抽取关联信息 → 通用元数据描述 → API/OAI-PMH 发布 → 中心库收割采集 → 本地解析/去重/重构 → 提供网站/API 检索并回链原数据。

## 6. 实验与结果
调查与设计研究，无传统实验，产出为现状分析（表 1、表 3）与设计方案（图 3/4/5）。
- **调研平台（10 个）**：Elsevier、Europe PMC、Dryad、ANDS、OpenAIRE、RD-Switchboard、Scholexplorer、ScienceDB、全球变化科学研究数据出版系统、Scholix 框架。
